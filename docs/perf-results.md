# Локальный перф-стенд mdns

Дата прогона: 2026-10-18. Ветка `feature/panel` (панель включена во всех
замерах). Стенд воспроизводимый: `scripts/perf-local.sh`, отдельный
`go`-модуль `e2e/perf` с генератором нагрузки и фейковым upstream'ом.

## Машина

| | |
|---|---|
| Модель | Apple M4, 16 GB RAM |
| ОС | macOS 27.0.1, arm64 (нативно, без Docker) |
| Go | go1.27.2 darwin/arm64 (в `go.mod` проекта — 1.26.0) |
| Сеть | loopback, plain DNS :53, DoH+панель :8443, DoT/DoQ :8853 |
| Демон | `bin/mdns` (текущая сборка ветки), self-signed TLS |

## Методика

Стенд поднимает:

* `e2e/perf/fakedns` — мгновенный локальный upstream на `127.0.0.1:53530`,
  отвечает A/AAAA и считает обслуженные запросы (печатает счётчик на SIGTERM);
* временный конфиг: домен `perf.test`, все четыре протокола, кэш 50 000,
  кольцо журнала 20 000, фильтр в режиме `zero` с 500 правилами
  `blk0.test … blk499.test`, панель включена (пароль `perf-panel-pass`,
  argon2id-хэш генерируется `e2e/perf/hashgen`), rate limit выключен;
* `e2e/perf/loadgen` — UDP- или DoH-генератор с миксом **70 % прогрев кэша /
  20 % заблокированные / 10 % уникальные** имена. Уникальные имена
  неймспейсятся идентификатором запуска, поэтому повторная фаза не «греет»
  их случайно. Генератор печатает человеческую сводку и строку
  `PERF_JSON {...}` (sent/done/errs/elapsed_s/qps/бакеты/p50/p95) для
  машинного разбора.

Фазы (пороги проверяются скриптом, при промахе прогон падает):

| Фаза | Профиль |
|---|---|
| smoke | 200 000 UDP-запросов, 64 воркера |
| main | 20 000 000 UDP-запросов, 64 воркера; через 60 с — проверки UI/API под нагрузкой |
| burst | 60 с × 128 воркеров |
| doh | 100 000 DoH GET, 32 воркера |
| post | остановка нагрузки, 2 с, RSS, счётчики, сходимость, отзывчивость TUI |

Под нагрузкой скрипт замеряет `mdns status` по unix-сокету, RSS, реакцию TUI
в tmux (переход `3` → «Запросы» и `1` → «Статус», капчуры панелей), логин в
веб-панель через форму (CSRF-токен обязателен, поэтому это GET `/login` →
POST с `csrf` + `password`) и время authenticated `GET /panel/`. Скриншот
панели снимает `.venv-pw` Playwright (`e2e/perf/shot.py`).

Счётчики сходятся по кумулятивным данным демона: `stats total`
(`/api/v1/stats`), кэш (hits/misses/entries), `filter.TotalBlocked`,
`upstreams[].Sent`, а также счётчик фейкового upstream'а. Ожидаемое число
запросов = сумма `sent` всех фаз + `prewarmed` (2000 имён на каждую UDP-фазу,
они тоже проходят через демон и кэш).

Про RSS: `ps -o rss` на macOS учитывает разделяемые страницы (dyld cache,
библиотеки) и завышает картину; рядом приведён `vmmap -summary` →
«Physical footprint» — собственный объём процесса. Порог скрипта — по `ps`
RSS: предупреждение выше 200 MB, жёсткий провал выше 400 MB.

### Память

| Момент | `ps` RSS | Physical footprint |
|---|---:|---:|
| старт | 21 MB | 9 MB |
| под нагрузкой (60-я секунда main) | 119 MB | — |
| после прогона | 294 MB | **131 MB** |

`ps` RSS вырос из-за разделяемых страниц и удержанной Go-кучи; собственный
footprint демона — 131 MB, что согласуется с прежними замерами (113 MB).
Роста с числом запросов нет: после main (20M) значения не меняются на burst
(+3.4M) и DoH (+100k). Жёсткий лимит 400 MB не близко; целевые 200 MB по
`ps` RSS формально превышены (предупреждение скрипта), по footprint — нет.

## Замечания

* Панель требует CSRF-токен на `POST /login`; «сырой» `curl -d password=…`
  из ранней формулировки задачи вернул бы 403. Стенд делает GET `/login`,
  забирает `mdns_login` + `csrf`, затем POST — как браузер.
* `ps` RSS на macOS — грубая метрика: она включает разделяемые страницы и
  сильно шумит между прогонами (198–294 MB при одном и том же footprint
  104–131 MB). Для оценки памяти демона используйте `vmmap`.
* Полный main (58.8k qps) немного ниже скретч-замера (61.0k): в текущей
  сборке включены панель и сбор статистики на каждом запросе, плюс
  сказался прогрев кэша уникальными именами. Для VPS числа будут другими.
* Числа VPS: **ожидаются** — Task 15 ждёт SSH; этот документ описывает
  только локальную машину.

## Как повторить

```sh
scripts/perf-local.sh                 # полный прогон (~7 минут)
PERF_TOTAL=200000 PERF_BURST=5s PERF_DOH_TOTAL=5000 PERF_PROBE_DELAY=0 \
  scripts/perf-local.sh               # быстрый прогон
PERF_PLAIN=5353 PERF_DOH=8443 PERF_DOT=8853 PERF_DOQ=8853 \
  scripts/perf-local.sh               # не занимать привилегированный :53
```

Логи фаз и `PERF_JSON` печатаются в stdout; временный каталог удаляется при
успехе и сохраняется (с путём в сообщении) при промахе порога.
