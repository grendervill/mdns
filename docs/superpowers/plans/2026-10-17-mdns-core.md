# mdns — ядро: план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Рабочий DNS-форвардер `mdns` на Go: принимает запросы по plain DNS,
DoH (h1/h2/h3), DoT и DoQ, ходит к выбранным upstream-провайдерам, кеширует,
маршрутизирует по стратегиям, следит за здоровьем upstream'ов и ведёт журнал
запросов; собирается в один бинарник и запускается командой `mdns serve`.

**Architecture:** Один Go-модуль `mydns`. Ядро собирается из независимых
пакетов: `config` (JSON-конфиг), `tlscert` (сертификаты), `transport`
(клиенты к upstream), `cache`, `upstream`+health, `routing` (стратегии),
`qlog` (журнал), `ratelimit`, `core` (оркестратор обработки), `dnsserver`
(листенеры), `app` (сборка всего) и `cmd/mdns` (CLI). Задачи выполняются
строго по порядку: каждый следующий пакет использует интерфейсы предыдущих,
зафиксированные в блоках **Interfaces**.

**Tech Stack:** Go 1.24+, `github.com/miekg/dns` (wire, UDP/TCP/TLS серверы
и клиенты), `github.com/quic-go/quic-go` (DoQ, HTTP/3), стандартная
библиотека для HTTP/1.1, HTTP/2, TLS, JSON, log/slog.

**Spec:** `docs/superpowers/specs/2026-10-17-mdns-design.md` (брать решения
оттуда; разделы 5–7, 15, 17). Более поздние подсистемы (фильтрация, API,
TUI, веб-панель, ACME, установщик, e2e в Docker) — отдельные планы.

## Global Constraints

- Go module: `mydns`, `go 1.24`. Бинарник один: `cmd/mdns` → `bin/mdns`.
- Каталог `bin/` в git не попадает (уже в .gitignore).
- Порты по умолчанию: plain 53, DoH 443, DoT 853, DoQ 853 (UDP). Только
  TCP для DoT, только UDP для DoQ.
- Конфиг: JSON `/etc/mdns/config.json` (путь — флаг `--config`), права файла
  0600, атомарная запись. Демон запускается `mdns serve`.
- Кеш: размер 10000 записей по умолчанию; TTL clamp min 0 / max 86400;
  негативный кеш по SOA; SERVFAIL/REFUSED/TC-ответы не кешируются.
- Health: проба `NS .`, timeout 2s, интервал 1s (активные) / 5s (остальные,
  если не использовались 30s), unhealthy после 3 ошибок подряд, EWMA
  alpha=0.2, штрафное значение при unhealthy 5s.
- Стратегии: `fastest` (по умолчанию), `failover`, `round_robin`, `random`.
- UDP-ответы ограничиваются 1232 байтами с корректным TC.
- Plain DNS: per-IP token bucket, по умолчанию 50 rps на IP; trusted CIDRs
  освобождаются от лимита; при превышении — drop по UDP, REFUSED по TCP.
- Журнал: ring buffer 10000 записей; файл JSONL — только если задан;
  ротация при 10 МБ (один файл `.1`, перезапись).
- Интерфейсы (TUI/веб) и русский язык — не в этом плане; здесь только
  английские сообщения логов и CLI.
- Все команды проверки — из корня репозитория: `go build ./...`,
  `go test ./...`, `go vet ./...`; Makefile добавляет удобные алиасы.

## Review Focus

Классы входов/условий, которые дизайн подразумевает, но ни одна задача не
проверяет по умолчанию; на каждый пункт ниже в задачах заведён тест с
пометкой **Review Focus**:

1. DoH GET `?dns=<base64url без padding>` — так делают curl и многие
   клиенты; должен работать, а не только POST.
2. Запрос без вопроса или с мусорными байтами — должен получить FORMERR,
   процесс не падает.
3. Ответ upstream > 1232 байт по UDP — клиенту уходит TC-ответ, полный
   ответ доступен по TCP.
4. Негативный кеш: повторный NXDOMAIN в пределах SOA TTL не ходит к
   upstream.
5. Таймаут одного upstream'а не должен задерживать ответ, если второй
   upstream здоров (failover по стратегии).
