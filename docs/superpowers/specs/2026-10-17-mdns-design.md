# mdns — дизайн v1

Дата: 2026-10-17
Статус: черновик на утверждение

## 1. Что это и зачем

`mdns` — саморазмещаемый DNS-сервис для личного VPS, который обслуживает
защищённые DNS-запросы устройств владельца (роутеры, телефоны, ноутбуки,
домашние серверы). Устанавливается на Ubuntu 24.04 или Debian 13 скриптом,
настраивается интерактивным визардом (TUI), после чего работает как демон
под systemd.

Ядро — собственный DNS-форвардер на Go: принимает запросы от устройств по
DoH (HTTP/1.1, HTTP/2, HTTP/3), DoT, DoQ и обычному DNS; фильтрует рекламу и
трекеры по выбранным блок-листам; разрешает запросы через выбранные публичные
upstream-провайдеры (Cloudflare, Google, Quad9, Яндекс и другие); маршрутизирует
по выбранной стратегии; кеширует ответы; ведёт журнал запросов. Готовые
DNS-движки (AdGuard Home, mosdns, dnsproxy, Caddy и т.п.) не используются — всё
ядро своё, включая движок фильтрации.

Сервис также предназначен быть upstream'ом для сторонних клиентов: например,
пользователь может вписать `https://<домен>/dns-query` в свой AdGuard Home, и
тот будет разрешать запросы через `mdns`. Фильтрация при этом выполняется на
стороне `mdns` и потому одинакова для любого клиента — и для устройств
напрямую, и для AdGuard Home.

Управление — двумя взаимозаменяемыми интерфейсами с полным паритетом функций:
TUI на машине (команда `mdns`) и веб-панель. Источник правды один — демон и
его API; TUI и веб — только клиенты.

## 2. Цели

- Установка одной командой на чистый Ubuntu 24.04 / Debian 13, интерактивный
  визард: домен → SSL → протоколы и порты → upstream-провайдеры (с живыми
  пингами) → стратегия маршрутизации → фильтрация (можно пропустить) →
  пароль панели → сводка со ссылками.
- Собственный DNS-движок: кеш, стратегии (fastest / failover / round-robin /
  random), health-check с автоматическим failover и возвратом к быстрому.
- Серверные протоколы: DoH (h1/h2/h3), DoT, DoQ, обычный DNS (53). Порты по
  умолчанию: 443, 853/tcp, 853/udp, 53; все настраиваются.
- Каталог публичных провайдеров с секциями «без фильтров» и «с фильтрами»,
  несколько провайдеров сразу, для каждого — выбор протокола обращения
  (DoH/DoT/DoQ/plain) и собственные кастомные upstream'ы.
- Блок-листы рекламы и трекеров (AdGuard, uBlock Origin, OISD, Hagezi, hosts и
  другие): выбор списков из каталога или свой URL, пользовательские правила,
  автоматическое обновление. Фильтрация выполняется на нашей стороне, поэтому
  работает независимо от выбранного upstream'а и от клиента.
- Наглядное измерение задержки до каждого upstream: в визарде, а затем в
  реальном времени в TUI и веб-панели.
- Бесплатные SSL-варианты на выбор: Let's Encrypt (по умолчанию), ZeroSSL,
  самоподписанный, произвольный ACME URL; автопродление без простоя.
- TUI и веб-панель: полный паритет, живые логи запросов, статусы, статистика.
- Скрипт установки одной командой; после установки — команда `mdns`.
- Локализация интерфейсов (TUI и веб) — русский; код, комментарии, логи,
  документация репозитория — английский.
- Полноценная проверка: unit-тесты, интеграционные тесты с фейковыми
  upstream'ами, docker-compose e2e на локальном домене без внешних сервисов.

## 3. Не-цели (в v1 не делаем)

- Рекурсивный резолвер и DNSSEC-валидацию (форвардер передаёт DNSSEC-записи,
  но сам их не валидирует; этим занимаются upstream'ы).
- Разные профили фильтрации для разных клиентов (per-client правила и
  расписания).
- Поддержку ОС кроме Ubuntu 24.04 и Debian 13, роли кроме «один сервер — один
  владелец», мульти-тенантность.
- DNS-01 challenge (нужен API регистратора; не планируем).
- Автообновление бинарника из интернета (обновление — переустановкой скриптом).
- Хранение кеша на диске между перезапусками.
- Публикацию в системные репозитории пакетов (deb-пакет).

## 4. Анти-цели (считаем провалом, даже если технически работает)

- Веб-панель доступна без аутентификации или по HTTP.
- Установщик/визард оставляет систему в полусостоянии при прерывании или
  повторном запуске ломает уже настроенное.
- Повторная настройка того же домена порождает лишние обращения к ACME
  (риск упереться в rate limit Let's Encrypt).
- Открытость системы как публичного DNS-резолвера для чужих людей: без
  лимитов, с возможностью амплификации (защита обязательна).
- Тихие сбои: ошибка транспорта/сертификата/upstream'а не видна в интерфейсах.

## 5. Ограничения и зафиксированные решения

- Язык: Go (актуальная стабильная версия). Один бинарник `mdns` с подкомандами;
  демон — `mdns serve` (запускается systemd-юнитом `mdns.service`).
- Зависимости: `miekg/dns` (DNS wire + серверы UDP/TCP), `quic-go` (DoQ и
  HTTP/3), `golang.org/x/crypto/acme` (ACME-клиент), `golang.org/x/net/http2`,
  TUI — `bubbletea`/`bubbles`/`lipgloss`. Веб-панель — серверные HTML-шаблоны
  + htmx + SSE, статика встроена через `embed`; без node-сборки.
- Конфигурация: `/etc/mdns/config.json` (версионированная схема, атомарная
  запись, права 600). Меняется только через API демона; ручные правки
  применяются при перезапуске.
- Данные: `/var/lib/mdns/` (сертификаты, ACME-аккаунт, бэкапы конфига),
  сокет: `/run/mdns/mdns.sock`.
- Архитектуры: amd64 и arm64.
- Локальные домены не могут получить публичный сертификат: в тестах
  используется локальный ACME-сервер (pebble) или самоподписанный сертификат.
- Тестируется в Docker локально; позже, по отдельной договорённости,
  разворачивается на VPS пользователя.
- Русский текст интерфейсов — мой выбор решения; если нужен другой язык,
  скажи.

## 6. Архитектура

Один бинарник, режимы:

```
mdns            → TUI (подключается к демону по unix-сокету)
mdns serve      → демон (systemd, root)
mdns setup      → визард первичной настройки (TUI-форма, вызывается установщиком)
mdns status|logs|version|diag → CLI-команды для скриптов и диагностики
mdns install|uninstall → установка/удаление (установщик делегирует сюда)
```

Демон (`mdns serve`) содержит:

- **Listeners** — UDP/TCP :53 (опционально), TLS :853, QUIC :853, HTTPS :443
  (h1/h2/h3). HTTPS-сервер одновременно обслуживает DoH `/dns-query`, API
  `/api/v1/*`, SSE `/api/v1/events` и веб-панель `/`.
- **DNSCore** — разбор запросов, фильтрация, кеш, выбор стратегии, форвардинг,
  сбор метрик и журнала.
- **FilterEngine** — блок-листы (adblock-подмножество, hosts, простые списки),
  компактный суффиксный индекс, пользовательские правила, автообновление
  списков; результат решения виден в журнале и статистике.
- **UpstreamTransports** — клиенты к провайдерам по plain UDP/TCP, DoT, DoH
  (h2/h3), DoQ; пулы соединений, таймауты, ретраи.
- **HealthMonitor** — периодические пробы каждого upstream'а, EWMA-задержка,
  состояние healthy/degraded/unhealthy, гистерезис возврата.
- **ACMEManager** — выдача, хранение, автопродление сертификата; listeners
  получают сертификат через `GetCertificate` (hot reload без простоя).
- **ControlAPI** — единый HTTP-API на unix-сокете (для TUI; доступ root) и на
  HTTPS (для веб-панели; сессии + пароль).
- **EventBus** — поток событий (запросы, статусы upstream'ов, состояние
  сертификата) для live-обновлений TUI и веба.

Паритет интерфейсов обеспечивается тем, что вся функциональность живёт в
ControlAPI, а TUI и веб-панель — тонкие клиенты. Любая настройка из веба
доступна в TUI и наоборот, включая визард.

## 7. DNS-ядро

- **Приём**: DoH по RFC 8484 (GET `?dns=` и POST), DoT по RFC 7858, DoQ по
  RFC 9250, plain по RFC 1035. Усечение ответов по UDP с корректным TC и
  fallback на TCP, как ожидают клиенты.
- **Форвардинг**: запрос маршрутизируется по выбранной стратегии; ответ
  передаётся клиенту как есть (с учётом кеша). EDNS0 passthrough; размер
  ответа UDP ограничивается разумным максимумом (1232) во избежание фрагментации.
- **Кеш**: в памяти, LRU, ключ (qname/qtype/qclass), негативный кеш по SOA
  TTL (RFC 2308) с ограничением. TTL clamp: min по умолчанию 0, max 86400,
  настраивается. Размер по умолчанию 10 000 записей. Сброс из интерфейсов.
- **Стратегии** (глобальная для набора выбранных upstream'ов):
  - `fastest` (по умолчанию) — самый низкий EWMA среди healthy; при сбое —
    следующий; возврат к лидеру после стабилизации (гистерезис).
  - `failover` — жёсткий порядок, заданный пользователем; переход при сбое.
  - `round_robin` — по кругу среди healthy.
  - `random` — равновероятно среди healthy.
  Если все unhealthy — попытки продолжаются по возрастанию задержки; при
  отсутствии ответа клиенту возвращается SERVFAIL. Каждое переключение видно
  в журнале и статистике.
- **Health-check**: DNS-проба `NS .` к upstream'у (по транспорту этого
  upstream'а) раз в 1 секунду для активных и раз в 5 секунд для остальных.
  Timeout 2 с. Правила: ответ получен и валиден → healthy (EWMA обновляется;
  NXDOMAIN/REFUSED от фильтрующих провайдеров не считаются сбоем); SERVFAIL
  или timeout повторно N раз → degraded → unhealthy. Возврат — после M
  успешных проб и стабильной задержки (параметры N/M — константы с
  комментариями, решим при реализации).
- **Защита от амплификации и доверенные сети**: plain DNS на 53 открыт в мир
  (иначе роутеры за домашним NAT не смогут им пользоваться), поэтому защита
  включена по умолчанию: per-IP token bucket (щедрый для домашнего NAT, за
  которым много устройств выглядит как один IP), ограничение размера UDP-ответа
  (1232) и отказ вместо TCP-fallback при превышении лимита. В конфиге есть
  список доверенных подсетей (trusted CIDRs): для них лимиты ослабляются или
  отключаются. Редактируется в TUI и веб-панели. DoH/DoT/DoQ защищены
  TLS/QUIC-хендшейком и в per-IP лимите по умолчанию не нуждаются (отдельный
  мягкий лимит на соединения — опция).
- **Журнал запросов**: ring buffer на 10 000 записей в памяти (ts, client IP,
  протокол, qname, qtype, rcode, upstream, транспорт, latency, cache hit,
  признак и источник блокировки). Опциональная запись JSONL
  `/var/log/mdns/requests.jsonl` с ротацией (по умолчанию выключено). IP
  клиентов виден владельцу — это его личный сервис.

## 8. Каталог upstream-провайдеров

- Секция «Без фильтров»: Cloudflare, Google, Quad9, Яндекс, AdGuard DNS,
  dns.sb, dns0.eu, Mullvad, ControlD (free), OpenDNS, LibreDNS и другие.
- Секция «С фильтрами» (семейные/безопасные): AdGuard Family, CleanBrowsing,
  OpenDNS FamilyShield, Cloudflare 1.1.1.3 (Family), ControlD (family/kids),
  Яндекс Family, dns0.eu и другие.
- Для каждого провайдера в каталоге: IPv4/IPv6-адреса, endpoints DoH/DoT/DoQ
  (если поддерживаются), человекочитаемое описание, секции каталога.
- Провайдеры и их endpoints выверяются при реализации (актуальность адресов
  проверяется тестами).
- Пользователь выбирает: набор провайдеров + для каждого транспорт
  (например, Cloudflare только DoH, Google — DoT). Допустимо выбирать одного
  провайдера несколькими транспортами как отдельные upstream'ы.
- **Кастомные upstream'ы**: пользователь может добавить свой (транспорт, адрес,
  порт, путь, опционально IP/SNI, заголовки). Пример — собственный AdGuard
  Home или корпоративный резолвер.
- Живые пинги: в визарде — таблица задержек с периодическим обновлением;
  после установки — постоянная таблица в TUI и веб-панели.

## 9. Фильтрация (блок-листы)

- **Назначение**: блокировка рекламы, трекеров и нежелательных доменов на
  уровне DNS — до обращения к upstream-провайдеру. Поэтому фильтры работают
  независимо от выбранного провайдера и от того, кто клиент: устройство
  напрямую, роутер или AdGuard Home — правила применяются одинаково.
- **Порядок обработки запроса** (в ядре, до кеша и форварда):
  1. пользовательское разрешение (allow) — пропустить всегда;
  2. пользовательская блокировка — заблокировать;
  3. исключения из списков (`@@`) — пропустить;
  4. правила списков — заблокировать.
  Заблокированный домен никогда не отдаётся из кеша; решение видно в журнале
  запросов с указанием источника (какой список или пользовательское правило).
- **Форматы списков**: доменное подмножество adblock (например,
  `||example.com^`, wildcard в доменной части, исключения `@@`), hosts-формат
  (`0.0.0.0 example.com`, `127.0.0.1 ...`) и простые списки доменов по строке.
  Косметические правила, правила с путями и regex-правила к DNS не применимы —
  аккуратно игнорируются, а в интерфейсах видно «применено N из M правил».
- **Каталог списков** (URL выверяются при реализации): реклама и трекеры —
  AdGuard DNS filter и Base, uBlock Origin filters, EasyList (доменные
  правила), Peter Lowe; комплексные — OISD (small/full), Hagezi (Pro, Pro++),
  Steven Black Unified, 1Hosts. Плюс произвольные списки по URL (сколько
  угодно).
- **Пресеты визарда**: «Выключено» (по умолчанию), «Базовый», «Строгий»,
  «Свой набор»; тонкая настройка — отметки отдельных списков.
- **Обновление**: автоматически раз в сутки (настраивается или выключается) и
  вручную; условные запросы (ETag/If-Modified-Since); неудачное обновление не
  ломает текущие данные; дата, размер и результат по каждому списку видны в
  интерфейсах.
- **Реакция на блокировку**: настраиваемо — `0.0.0.0` + `::` (по умолчанию),
  `NXDOMAIN` или `REFUSED`. Счётчики: всего заблокировано, топ доменов, вклад
  каждого списка.
- **Пользовательские правила**: блокировка или разрешение домена (точный
  домен или поддомены) из TUI и веб-панели, в том числе кнопкой «разрешить»
  прямо из журнала запросов.
- **Производительность**: списки на миллионы доменов; компактный суффиксный
  индекс, атомарная подмена набора при обновлении без остановки обслуживания;
  бюджет памяти уточняется при реализации (для тяжёлых пресетов — предупреждение).

## 10. Сертификаты

- Варианты при настройке: Let's Encrypt (по умолчанию), ZeroSSL (если
  требуется EAB — визард запросит данные), самоподписанный (для тестов и
  локальных сетей, с предупреждением), произвольный ACME directory URL
  (для pebble в тестах и внутренних CA). Buypass включаем только если на
  момент реализации его ACME ещё работает — проверяем факт и решаем.
- Вызовы ACME: TLS-ALPN-01 (порт 443 — всегда доступен, т.к. наш HTTPS-сервер
  слушает там) и HTTP-01 (порт 80). Если DoH не на 443, TLS-ALPN-01
  невозможен: включается HTTP-01 и на время работы в ACME-режиме поднимается
  слушатель :80, отвечающий только на `/.well-known/acme-challenge/...`
  (остальное — 404); визард предупреждает об этом и о требованиях ACME при
  изменённых портах.
- Продление: ежедневная проверка, продление за 30 дней до истечения; hot
  reload через `GetCertificate` без разрыва соединений; уведомление о
  неудачах в TUI/веб и journald.
- **Если сертификат получить не удалось** (домен ещё не резолвится, порты
  заняты, лимиты ACME): setup не зависает и не оставляет полусостояние. Все
  этапы визарда завершаются, демон стартует в режиме «без TLS»: работает
  обычный DNS на 53 и локальное управление (TUI по SSH через unix-сокет),
  TLS-листенеры (DoH/DoT/DoQ) не поднимаются и веб-панель недоступна.
  Исключение: в ACME-режиме слушатель :443 при DoH на 443 поднимается
  сразу — он необходим для TLS-ALPN-01; до получения сертификата он
  отвечает только на ACME-челлендж, обычные TLS-соединения не проходят.
  Пользователю показывается конкретная ошибка и три пути: повторить попытку
  сейчас / изменить настройки (порты, домен) / продолжить — тогда включаются
  фоновые повторные попытки с экспоненциальным разбросанным бэкоффом (от
  5 минут до 6 часов), чтобы не расходовать лимиты ACME. Статус «сертификат:
  ожидание/ошибка» виден в TUI и (когда появится TLS) в вебе. При появлении
  сертификата TLS-листенеры поднимаются автоматически без перезапуска демона.
- Повторный запуск визарда с тем же доменом: если в хранилище есть валидный
  (или не истёкший с запасом) сертификат — новый ACME-запрос не делается.
- Ключи: ECDSA P-256; хранение в `/var/lib/mdns/certs`, права 600.
- Личный бэкап: сертификат и ACME-аккаунт переживают переустановку
  (удаляются только при явном полном uninstall с подтверждением).

## 11. Установщик

- Хостинг: публичный GitHub-репозиторий `github.com/grendervill/mdns`;
  релизы — GitHub Releases (linux amd64/arm64 + SHA256SUMS) по тегам `vX.Y.Z`,
  сборка — GitHub Actions. `install.sh` живёт в корне репозитория.
- «Одна команда»:
  `curl -fsSL https://raw.githubusercontent.com/grendervill/mdns/main/install.sh | sudo bash`
  (плюс `--version vX.Y.Z` для конкретной версии и `--local ./mdns` —
  локальный бинарник для тестов и VPS). `install.sh` — тонкий
  бутстрап: определение OS/архитектуры, скачивание бинарника из релиза
  с проверкой SHA256, установка в `/usr/local/bin/mdns` и запуск
  `mdns install "$@"`. Вся системная работа — в `mdns install` (Go,
  тестируемо); в Docker-e2e используется `--local`.
- Preflight (`mdns install`): root; дистрибутив по `/etc/os-release`
  (Ubuntu 24.04/Debian 13, иначе отказ); arch amd64/arm64; systemd;
  свободные порты (с разбором занятости); конфликт с
  `systemd-resolved` на :53 — предлагается отключение stub listener;
  проверка, что A/AAAA домена указывает на этот сервер (предупреждение,
  не блокировка); свободное место.
- Действия: установка бинарника в `/usr/local/bin/mdns`, создание каталогов
  конфига/данных, systemd-юнит `mdns.service` (Restart=always), запуск
  `mdns setup`, открытие портов в ufw (если он активен; иначе — инструкция,
  чужие firewall-настройки не трогаем молча), финальная сводка.
- Идемпотентность: повторный запуск = обновление бинарника и/или перенастройка
  без потери данных; все шаги транзакционны, при прерывании визарда демон не
  стартует в полусостоянии.
- Завершение setup имеет три исхода: успех / успех с предупреждением
  (например, сертификат в ожидании — работает обычный DNS, TLS включится
  автоматически) / ошибка до конфигурации. Полусостояний нет ни в одном
  случае (см. §10 про политику при неудаче сертификата).
- Режим `--non-interactive` с флагами (домен, провайдеры, порты, ACME, пароль)
  — для автоматизации и e2e-тестов в Docker.
- `mdns uninstall` — удаление с подтверждением; отдельный флаг — сохранить
  сертификаты/конфиг (по умолчанию сохраняем, удаляем только по явному запросу).
- Формат сводки в конце установки: домен, включённые протоколы и ссылки для
  устройств (DoH URL, DoT `tls://`, DoQ `quic://`, plain `host:53`), адрес
  веб-панели, логин/пароль, статус сертификата, текущий лучший upstream,
  статус фильтрации (списки и число активных правил).

## 12. TUI

Экраны (bubbletea, русский язык, тёмная тема терминала):

1. **Статус** — домен, сертификат (провайдер, срок), протоколы/порты/ссылки,
   таблица upstream'ов с живыми задержками и состоянием, статистика кеша,
   лента последних запросов.
2. **Визард настройки** — те же шаги, что в установке: домен → сертификат →
   протоколы/порты → провайдеры и транспорты (с пингами) → стратегия →
   фильтрация (пресеты списков) → пароль панели. Доступен повторно из меню.
3. **Запросы** — live-таблица с паузой, фильтрами (протокол, домен, клиент),
   прокруткой; заблокированные записи помечены, из строки можно добавить
   домен в исключения одним действием.
4. **Upstream'ы** — детально: latency-график (спарклайн), success rate,
   ошибки, счётчики, ручное вкл/выкл, приоритет для failover.
5. **Фильтры** — списки (вкл/выкл, обновление, статус, размер, покрытие
   правил), пользовательские правила, режим блокировки, статистика и топ
   заблокированных доменов.
6. **Настройки** — все параметры: порты, протоколы, стратегия, TTL/кеш,
   лимиты plain DNS, пароль панели, кастомные upstream'ы, домен/сертификат.
7. **Диагностика** — статус сервисов, journald-логи, конфигурация путей,
   `mdns diag` (self-check: порты, запись, сертификат, upstream'ы, фильтры).

## 13. Веб-панель

- Доступ: `https://<домен>/` (та же TLS-точка, что DoH; `/dns-query` не
  затрагивается). Аутентификация: логин `admin` + пароль из визарда (можно
  сменить), session cookie (HttpOnly/Secure/SameSite), CSRF-токен, троттлинг
  логина. Внешний вид разрабатывается по скиллу frontend-design, макеты
  показываются пользователю до реализации.
- Разделы — зеркало TUI: Статус, Запросы (live), Upstream'ы, Фильтры,
  Настройки, Сертификат, Обслуживание (рестарт listeners, бэкапы конфига).
- Live-обновления через SSE. Работает на телефоне (адаптивная вёрстка) —
  владелец сможет посмотреть состояние и поменять настройки с телефона.

## 14. CLI

- `mdns` — TUI.
- `mdns status` — краткая сводка (для скриптов; JSON-флаг).
- `mdns diag` — диагностика (порты, сертификат, upstream-пинги, запись,
  состояние списков фильтрации).
- `mdns logs [-f]` — журнал демона/запросов.
- `mdns setup` — визард; `mdns serve` — демон; `mdns install/uninstall`.
- `mdns version`.

## 15. Безопасность

- Управление только по HTTPS/локальному сокету; unix-сокет доступен
  root-группе.
- Пароль панели хранится как argon2id-хэш; в логах секретов нет.
- Plain DNS на 53 — rate limit и защита от амплификации по умолчанию.
- Списки фильтрации скачиваются только по HTTPS; их содержимое парсится как
  данные (только доменные правила) и никогда не исполняется.
- Приватные ключи — 600, каталог данных — 700.
- Из сервиса нет исходящих соединений, кроме ACME, выбранных upstream'ов и
  проверки обновлений (последней в v1 нет).
- Никакой телеметрии.

## 16. Тестирование

- Unit: конфиг/валидация, кеш, стратегии и их переключения, парсинг
  endpoints каталога, ACME-хранилище, rate limit, API+auth, парсер блок-листов
  (adblock-подмножество, hosts, простые списки) и приоритеты правил.
- Integration: фейковые upstream-серверы в процессе теста (plain, DoT, DoH,
  DoQ) — стратегии, failover, кеш, таймауты, усечение UDP; фильтрация по
  спискам и исключениям, обновление списков из фейкового источника, атомарная
  подмена набора при обновлении.
- Docker e2e (docker-compose, локально): контейнер ubuntu:24.04 и/или
  debian:13 + наш установщик в `--non-interactive` с локальным доменом
  `mdns.test`, ACME через pebble (локальный, без интернета) и вариант
  self-signed; клиентские проверки: `dig`/`kdig`/`q`/`curl`, проверка
  сертификата; скачивание блок-листа с локального HTTP-сервера и проверка
  блокировки по всем протоколам; веб-панель через Playwright; TUI — в tmux
  с проверкой вывода.
- Верификация глазами: скриншот TUI и веб-панели (Playwright) перед отчётом
  о готовности — по моим правилам работы с UI.
- VPS-тест — отдельно позже, по SSH-доступу от пользователя: полный прогон,
  после — очистка с сохранением сертификата и настроек продления (если
  пользователь не скажет иначе).

## 18. Мои решения (проверить при чтении)

- Go, один бинарник, bubbletea для TUI, веб без node — серверные шаблоны +
  htmx + SSE.
- Русский интерфейс, английский код.
- Plain DNS на 53 включён по умолчанию (роутеры часто умеют только его),
  с защитой и возможностью отключить.
- Кеш включён по умолчанию; журнал в файл — по желанию.
- Краевые случаи, решённые без пользователя (проверь при чтении): политика
  при неудаче выпуска сертификата (см. §10) и доверенные сети для plain DNS
  (см. §7) — по умолчанию :53 открыт миру с лимитами, потому что иначе
  роутеры за NAT не смогут подключаться.
- Фильтры: собственный движок (без сторонних блокировщиков), поддержка
  доменных правил adblock-подмножества, hosts и простых списков; косметика,
  пути и regex игнорируются с подсчётом «применено N из M». По умолчанию
  фильтрация выключена, визард предлагает пресеты. Реакция на блокировку по
  умолчанию — `0.0.0.0`/`::` с возможностью выбрать `NXDOMAIN` или `REFUSED`.
- Имя команды `mdns` совпадает с аббревиатурой multicast DNS — это осознанно,
  сервис multicast DNS не реализует и не конфликтует (слушает другие порты).
